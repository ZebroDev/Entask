# `ja`：第五語系（日本語）

## 性質

**這裡的譯文尚未經母語者審閱。** 它們由代理初譯＋逐條審閱產生，可用、用詞一致，
但**不是**產品品質的譯文，也**不得**在文件、commit 或對外說明中描述成「已完成翻譯」。

`zh-TW` 是來源語系，也是 key 的權威；`ja` 是它的鏡射。key 集合必須與 `zh-TW` 完全相等，
由 `web/scripts/check-locale-parity.mjs` 在 CI 守住（比 key 集合，不是比檔案內容）。

## 為何這個檔名（而不是 `_meta.json`）

`locales/ja/` 底下的**每個 `.json` 都是一個 namespace**。放一個 `_meta.json` 會讓上面那條
集合相等檢查多比對一個 zh-TW 沒有的 namespace，於是永久紅燈。說明只能是非 JSON 檔。

## 涵蓋範圍：也包含伺服器端的匯出資源檔

`src/Entask.Api/Resources/export.ja.json`（**30 條**：匯出檔的工作表名、表頭與複製標題樣板）
與本目錄同批產出，**適用上面那一整節的標示**——它同樣未經母語者審閱。它沒有專屬的複閱清單
（多數是名詞），但要知道一個**既有的**系統性缺口：匯出標籤的測試覆蓋本來就不完整
（19 個 worklog key 只有 5 個被斷言；兩個常數互換會通過所有關卡、只在 Excel 裡顯形）。
四個語系**不會讓它變好，只會讓它變寬**——本階段不修。

`rating.suffix` 是在語系產出前才加進去的（P-C Followups），所以條數是 **30** 而不是
本目錄同期文件裡常見的 29。

## 語域與標點

- 語域：**敬体（です・ます）**，全檔一致。
- 標點：`、` 與 `。`；**引號用 `「 」`**（不套用 en 的彎引號——引號是語系相關的排版決定）。
- 省略號：`…`（不套用 en 的 ASCII `...`）。
- 複數：`ja` 只有 `other` 一個類別，與 `zh-TW` 同形。
- `common` 的 `separator.list`（`、`）與 `separator.label`（`：`）與 `zh-TW` **逐位元組相同**：
  那是**全形標點**，日文的読点就是 `、`、冒號就是 `：`，**不是漏譯**（兩條都已登記於
  `check:copy` 的白名單）。

判準（實查於 2026-09-20，本檔寫入時）：10 個語系檔的 ASCII `...` **0 處**、`…` **37 處**；
`error.json` 的 **81** 條葉節點裡以 `。` 或 `.` 收尾的**各 0 條**——錯誤訊息不加句尾句號，
與 `zh-TW`／`zh-CN`／`es-419` 同一個判準（`en` 的 `endDot` 是 **15**，是**尚未裁定**的既有分歧，
要統一請連 `en` 一起裁定，**不要單獨改本語系**）。
