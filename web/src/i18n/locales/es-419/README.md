# `es-419`：第四語系（拉美中性西語）

## 性質

**這裡的譯文尚未經母語者審閱。** 它們由代理初譯＋逐條審閱產生，可用、用詞一致，
但**不是**產品品質的譯文，也**不得**在文件、commit 或對外說明中描述成「已完成翻譯」。

`zh-TW` 是來源語系，也是 key 的權威；`es-419` 是它的鏡射。key 集合必須與 `zh-TW` 完全相等，
由 `web/scripts/check-locale-parity.mjs` 在 CI 守住（比 key 集合，不是比檔案內容）。

`es-419` 是**拉美中性西語**（Latin American Spanish）：不含西班牙本土用法，
也不是任何單一國家的西語。巴西講的是 `pt-BR`，不在本專案的語系清單內。

## 為何這個檔名（而不是 `_meta.json`）

`locales/es-419/` 底下的**每個 `.json` 都是一個 namespace**。放一個 `_meta.json` 會讓上面那條
集合相等檢查多比對一個 zh-TW 沒有的 namespace，於是永久紅燈。說明只能是非 JSON 檔。

## 涵蓋範圍：也包含伺服器端的匯出資源檔

`src/Entask.Api/Resources/export.es-419.json`（**30 條**：匯出檔的工作表名、表頭與複製標題樣板）
與本目錄同批產出，**適用上面那一整節的標示**——它同樣未經母語者審閱。它沒有專屬的複閱清單
（多數是名詞），但要知道一個**既有的**系統性缺口：匯出標籤的測試覆蓋本來就不完整
（19 個 worklog key 只有 5 個被斷言；兩個常數互換會通過所有關卡、只在 Excel 裡顯形）。
四個語系**不會讓它變好，只會讓它變寬**——本階段不修。

`rating.suffix` 是在本語系產出前才加進去的（P-C Followups），所以條數是 **30** 而不是
本目錄同期文件裡常見的 29。

## 語域：拉美中性（複閱與後續修改的判準）

判準是「墨西哥／哥倫比亞／阿根廷的使用者會不會這樣說」：

- 第二人稱一律 `tú`（不用 `vos`，也不用西班牙的 `vosotros`）；複數用 `ustedes`，不用 `vosotros`。
- `computadora`（不是 `ordenador`）、`celular`（不是 `móvil`）、`departamento`（不是 `piso`）。
- 不用 `coger`（在拉美是粗話）。
- **`puntuación` 是評分**（`Review.Score`，1–5 分）、**`calificación` 是評等**（`S`／`A`／`B`／`C`）。
  這兩個詞在一般西語裡可互換，本專案把它們**釘成兩個不同的概念**，不要混用。
- 錯誤訊息**不加句尾句號**。實查：`zh-TW`／`zh-CN`／`es-419` 的 `error.json` 各 81 條葉節點，
  以及 C# 的 `ErrorMessages.cs`，帶句尾句號的都是 **0 條**。**`en` 有 15 條例外**
  （`*notFound` 那一族，且 `en` 的複閱從未提過標點）——那是**尚未裁定**的既有分歧，
  本語系照來源語系與多數；要統一請連 `en` 一起裁定，**不要單獨改本語系**。

## 複數：本語系是唯一需要 `many` 的

`es-419` 的類別是 `one`／`many`／`other`（`zh-TW`／`zh-CN`／`ja`／`ko` 只有 `other`）。
`many` 只在**整百萬**選得到（實測：`select(999999)` 是 `other`、`select(1000000)` 是 `many`、
`select(2000000)` 也是 `many`，但 `select(1000001)` 回到 `other`）——實務上幾乎不會出現在計數句，
但**仍然要放**：少了它，`check-locale-parity.mjs` 的檢查 5 會紅，而那個紅燈是對的
（它保證本語系在**任何**數量下都拿得到自己的字串，而不是掉回 zh-TW 的中文）。

**`_many` 允許與 `_other` 逐字相同**——當那個值不是「數字＋名詞」的片語時（純單位標籤、
括號內的計數），三格同形是正確的，不是漏譯。判準是**三格都唸得通**，不是三格都不同。
