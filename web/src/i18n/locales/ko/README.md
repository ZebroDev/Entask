# `ko`：第六語系（한국어）

## 性質

**這裡的譯文尚未經母語者審閱。** 它們由代理初譯＋逐條審閱產生，可用、用詞一致，
但**不是**產品品質的譯文，也**不得**在文件、commit 或對外說明中描述成「已完成翻譯」。

`zh-TW` 是來源語系，也是 key 的權威；`ko` 是它的鏡射。key 集合必須與 `zh-TW` 完全相等，
由 `web/scripts/check-locale-parity.mjs` 在 CI 守住（比 key 集合，不是比檔案內容）。

## 為何這個檔名（而不是 `_meta.json`）

`locales/ko/` 底下的**每個 `.json` 都是一個 namespace**。放一個 `_meta.json` 會讓上面那條
集合相等檢查多比對一個 zh-TW 沒有的 namespace，於是永久紅燈。說明只能是非 JSON 檔。

## 涵蓋範圍：也包含伺服器端的匯出資源檔

`src/Entask.Api/Resources/export.ko.json`（**30 條**：匯出檔的工作表名、表頭與複製標題樣板）
與本目錄同批產出，**適用上面那一整節的標示**——它同樣未經母語者審閱。它沒有專屬的複閱清單
（多數是名詞），但要知道一個**既有的**系統性缺口：匯出標籤的測試覆蓋本來就不完整
（19 個 worklog key 只有 5 個被斷言；兩個常數互換會通過所有關卡、只在 Excel 裡顯形）。
四個語系**不會讓它變好，只會讓它變寬**——本階段不修。

`rating.suffix` 是在語系產出前才加進去的（P-C Followups），所以條數是 **30** 而不是
更早的說明裡常見的 29。

## 語域與標點

- 語域：**합니다体**，全檔一致，**不得混入 해요체 或 반말**。
- **工時一律 `공수`**——同一個概念不得寫成 `작업 시간` 或 `보고 작업`。（`시간` 這個字本身
  仍合法：`공수 (시간)` 這種括號補注與「時鐘時間」義的用法都在——下面的量測看的是趨勢，
  不是把 `시간` 歸零。）
- **審查一律 `리뷰`**——不得寫成 `검토`。
- 標點：半形 `,`／`:`／`.` 與括號 `( )`；**引號用 `“ ”`**（與 `ja` 的 `「 」` 不同
  ——引號是語系相關的排版決定）。
- 省略號：`…`（不套用 en 的 ASCII `...`）。
- 複數：`ko` 只有 `other` 一個類別，與 `zh-TW` 同形（`Intl.PluralRules("ko")`）。
- 句尾句號：**保留**——完整句一律加 마침표
  （例：`이 첨부 파일을 찾을 수 없습니다. 이미 삭제되었을 수 있습니다.`）。這與
  `zh-TW`／`zh-CN`／`es-419`／`ja`（錯誤訊息不加句尾句號）**判準不同**，是韓文書寫的慣例；
  **要收斂請連其他語系一起裁定，不要單獨改本語系**。

判準（實查於 2026-09-20，本檔寫入時）：10 個語系檔的 ASCII `...` **0 處**、`…` **37 處**；
`“` 與 `”` **各 27 處**（成對）；`error.json` 的 **81** 條葉節點裡以 `.` 收尾的 **18 條**、
以 `。` 收尾的 **0 條**——以 `.` 收尾的全部是完整句訊息（十個檔合計 **55 條**）。

量測指令（**不要寫死條數**）：

```
cd web/src/i18n/locales
for f in ko/*.json; do echo -n "$f "; LC_ALL=C.UTF-8 grep -o '공수' "$f" | wc -l; done
LC_ALL=C.UTF-8 grep -c '검토' ko/*.json     # 應全為 0
LC_ALL=C.UTF-8 grep -c '시간' ko/*.json     # 不是 0——要看的是它有沒有出現在「工時」義上
LC_ALL=C.UTF-8 grep -o '…' ko/*.json | wc -l
LC_ALL=C.UTF-8 grep -o -F '...' ko/*.json | wc -l   # 應為 0
```
