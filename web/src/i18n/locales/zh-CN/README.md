# `zh-CN`：第三語系

## 性質

**這裡的譯文尚未經母語者審閱。** 它們由 zh-TW 逐條轉換＋審閱產生（**不是機器轉換**——
一簡對多繁反向會錯，且詞彙整組不同），可用、用詞一致，但**不是**產品品質的譯文，
也**不得**在文件、commit 或對外說明中描述成「已完成翻譯」。

`zh-TW` 是來源語系，也是 key 的權威；`zh-CN` 是它的鏡射。key 集合必須與 `zh-TW` 完全相等，
由 `web/scripts/check-locale-parity.mjs` 在 CI 守住（比 key 集合，不是比檔案內容）。

## 為何這個檔名（而不是 `_meta.json`）

`locales/zh-CN/` 底下的**每個 `.json` 都是一個 namespace**。放一個 `_meta.json` 會讓上面那條
集合相等檢查多比對一個 zh-TW 沒有的 namespace，於是永久紅燈。說明只能是非 JSON 檔。

## 涵蓋範圍：也包含伺服器端的匯出資源檔

`src/Entask.Api/Resources/export.zh-CN.json`（30 條：匯出檔的工作表名與表頭）與本目錄同批產出，
**適用上面那一整節的標示**——它同樣未經母語者審閱。它沒有專屬的複閱清單（只有 30 條，且多數是名詞），
但要知道一個**既有的**系統性缺口：匯出標籤的測試覆蓋本來就不完整（19 個 worklog key 只有 5 個被
斷言；兩個常數互換會通過所有關卡、只在 Excel 裡顯形）。四個語系**不會讓它變好，只會讓它變寬**
——本階段不修。
